# Olist 电商平台经营分析与用户增长研究

基于巴西 **Olist** 电商平台真实交易数据（2016–2018）的端到端数据分析项目，覆盖「数据审计 → SQL 业务分析 → Python 机器学习建模 → 可视化看板」完整链路，从**订单履约、用户体验、用户增长**三个维度拆解平台经营表现。

## 项目概述

Olist 是巴西最大的电商平台之一，连接中小卖家与终端消费者。本项目以其公开数据集为对象，回答以下业务问题：

- 平台交易规模如何随时间变化？销售额在哪些品类、哪些卖家中集中？
- 订单履约效率如何？配送延迟的分布与地区差异在哪里？
- 用户购买行为呈现什么特征？复购率处于什么水平？
- 哪些因素与用户评分相关？能否基于下单时可获得的信息预测订单的延迟风险与评分高低？

项目采用分阶段递进的方式组织，每个阶段产出一份分析报告，最终以交互式数据看板的形式可视化全部结论。

## 数据说明

数据来自巴西 Olist 公开数据集，覆盖 **2016-09 至 2018-08** 的交易记录，共 9 张业务表，构成一个完整的电商订单域模型：

| 数据表 | 行数 | 说明 |
|---|---:|---|
| `olist_orders` | 99,441 | 订单主表：状态与各环节时间戳 |
| `olist_order_items` | 112,650 | 订单商品明细：价格、运费、卖家 |
| `olist_order_payments` | 103,886 | 支付信息：方式、期数、金额 |
| `olist_order_reviews` | 99,224 | 评论与评分（1–5 分） |
| `olist_products` | 32,951 | 商品主数据与品类归属 |
| `olist_sellers` | 3,095 | 卖家主数据：城市、州 |
| `olist_customers` | 99,441 | 客户主数据与唯一用户 ID |
| `olist_geolocation` | 1,000,163 | 邮编经纬度地理信息 |
| `category_translation` | 71 | 品类名称翻译（葡萄牙语 → 英语） |

> 数据货币单位为**巴西雷亚尔（R$）**。品类名称使用葡萄牙语，通过 `category_translation` 表映射为英语。

## 分析流程

项目分三个阶段推进，每阶段产出一份总结报告（位于 `outputs/`）。

### 阶段一：数据审计（`01_data_audit.ipynb`）

盘点 9 张数据表，完成数据质量审计：

- 行数、列数、字段类型与文件规模盘点
- 缺失值与完全重复行检查
- 主键唯一性与完整性校验（含 `order_reviews` 表的候选键组合排查）
- 基础探索：订单状态分布、月度订单量、配送时效、评分分布

### 阶段二：SQL 业务分析（`02_sql_analysis.ipynb`）

将 CSV 导入 SQLite 后，围绕四个维度开展业务分析：

- **平台经营**：月度订单量、商品销售额与环比增速、品类结构与销售排名、卖家经营表现
- **订单履约**：整体与分月/分州配送延迟率、实际配送时长
- **用户行为**：购买频次分布、复购率、首次购买月份与复购 cohort
- **用户体验**：评分分布、低分品类与地区、配送时长/价格/运费与评分的关系

### 阶段三：Python 建模（`03_python_modeling.ipynb`）

构建两个订单级分类任务，并进行模型比较与可解释性分析：

1. **配送延迟预测**（二分类）：基于 96,470 笔已送达订单，识别最终延迟送达的订单
2. **评论评分三分类**：基于 98,673 笔订单与 108 个特征，预测订单的评分档位（低 / 中 / 高）

评论评分任务比较了逻辑回归（LR）、随机森林（RF）、梯度提升决策树（GBDT）与多层感知机（MLP），并采用 SHAP（PermutationExplainer）对最优模型进行特征重要性解释。

## 核心发现

1. **交易规模增长后趋于稳定** — 商品销售额在 2017 年快速攀升，2017-11 达峰值约 98.8 万；2018 年春季仍处高位但增速放缓，平台增长进入瓶颈。
2. **销售额集中在少数头部品类** — `health_beauty`（9.26%）、`watches_gifts`（8.87%）、`bed_bath_table`（7.63%）等头部品类贡献主要销售额。
3. **用户复购比例较低** — 仅约 3.0% 的用户产生至少两笔已送达订单，平台以单次购买为主，留存与复购空间较大。
4. **配送时效与评分强相关** — 低分订单平均送达 20.2 天，高分订单仅 11.1 天；延迟订单评分 2.57，准时订单 4.29，履约体验是评分的关键驱动。
5. **局部品类与卖家存在低分信号** — 男装、办公家具等品类低分率偏高（需注意低样本量对比例的放大影响）。
6. **GBDT 在四类模型中表现最优** — 评论评分三分类中，GBDT 的 ROC-AUC（0.6142）、Macro-F1（0.3255）、准确率（0.7762）均为最高，但受类别不平衡影响，区分能力仍有提升空间。

## 可视化看板

项目结论以**交互式数据看板**形式呈现，位于 `website/` 目录：

- **8 项核心 KPI**：已送达订单、销售额、客单价、评分、延迟率、复购率等
- **16 个交互式图表**：月度趋势、品类结构、地区延迟、评分分布、模型对比、SHAP 特征重要性等
- **交互能力**：滚动导航、悬浮提示、趋势/品类指标切换、响应式布局

**打开方式**：直接用浏览器打开 `website/index.html` 即可（数据已内联，无需联网、无需启动服务）。

如需更新看板数据，在项目根目录执行：

```bash
python website/build_data.py
```

脚本会从 `data/olist.db` 重新聚合数据，并更新 `website/js/data.js` 与 `website/data.json`。

## 快速开始

**环境依赖**

```bash
pip install pandas numpy scipy scikit-learn xgboost shap matplotlib jupyter
```

**复现步骤**

1. 数据准备：原始 CSV 已置于 `data/raw/`（`archive.zip` 为其压缩备份）
2. 运行 `notebooks/01_data_audit.ipynb`，完成数据审计与探索
3. 运行 `notebooks/02_sql_analysis.ipynb`，构建 `data/olist.db` 并执行业务分析
4. 运行 `notebooks/03_python_modeling.ipynb`，完成特征工程、模型比较与 SHAP 解释
5. （可选）运行 `python website/build_data.py` 刷新看板数据，打开 `website/index.html`

## 说明

- 各阶段总结详见 `outputs/` 目录下的分析报告，Notebook 中的结论与报告保持一致。
- 模型比较基于当前特征与参数设定，未进行全面的超参数搜索；SHAP 结果基于抽样订单，属探索性证据。
- 特征重要性反映的是模型预测中的相对贡献，**不构成因果关系**，相关结论需结合业务进一步验证。
